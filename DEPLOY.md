## Как обновить сайт после изменений

1. Собрать свежую папку `dist/` в этом проекте (`npm run build`). Сборка — под Windows; в WSL не собирать (там нет установленных под Windows `node_modules`).
2. Заменить содержимое ветки `gh-pages` новой сборкой: в локальной копии репозитория (`/home/alex/trenirovki`) взять новое содержимое `dist/`, очистить от старых файлов ветку `gh-pages`, скопировать туда всё содержимое нового `dist/`, убедиться, что в корне остался пустой файл `.nojekyll`, затем `git add -A`, `git commit -m "Публикация"`, `git push origin gh-pages`.
3. Чтобы было видно новые файлы в рабочей копии, в неё нужно переложить и обновлённые исходники (`src/`, `public/`, `tests/`, конфиги) — их коммитит ветка `main`.
4. GitHub Pages пересоберёт сайт автоматически — обычно в течение 1–3 минут после пуша.
